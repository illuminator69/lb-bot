## The finding that shaped the work

The task was "implement the new features from
`design_handoff_lb_bot_frontend/`", which opens with a README declaring itself a
**ground-up rewrite** of the frontend. It isn't. Diffing the bundle against the
repo first:

- `design_handoff_lb_bot_frontend/README.md` is **byte-identical** to `handoff.md`.
- Its `BACKEND_RECOMMENDATIONS.md` differs from the root copy by **one bullet**
  (§10, gap-queue cursor).
- `ARTIST_IMPLEMENTATION_HANDOFF.md` differs from `ARTIST_PAGE_HANDOFF.md`, but
  everything it specifies — index-first artist screen, cover-forward grouped
  discography, the four album-state tones, `ArtistTile`/`ReleaseTile`/
  `TrackList`/`SortToggle` — is already in `web/src`.

So the four-screen rewrite and the Artist tab were already built. The genuinely
new document is **`BACKEND_HANDOFF_NEW_ELEMENTS.md`**, which is explicit about
what it is: ten UI elements that are "client-only mock state (a plain
`this.state` field with no server round-trip)", listed so someone can put real
endpoints behind them. That, plus the one added §10 bullet, was the actual job.

Taking the README at its word would have cost a full pass rebuilding working
code. This is recorded in `README.md`'s repo map so the next reader diffs first.

## What was built

**Header (items 1–2).** The wordmark navigates to Fill gaps. The "Live · 3s"
indicator became a button that forces a real resync of the current screen; it
had been flipping a boolean for 700 ms and fetching nothing, which is worse than
no button — it *claims* a refresh happened.

**Fill gaps (items 3, 8, 9).**

- A floating jump-to-cursor control in the queue rail, shown only when the
  selected row scrolls out of view. Driven by an `IntersectionObserver` against
  the scroll container rather than scroll-offset math: the rail becomes
  *horizontal* below 860 px, so offset math would need a second implementation,
  and it would drift the moment the list reordered.
- "Show files" on the chosen-source card, expanding the peer's real folder
  listing. The mock synthesized filenames from the tracklist
  (`chosenFiles`), which can only ever restate the row above it — the handoff
  says as much ("useless once it just re-displays the track title with an
  assumed extension"). Extracted `useSourceFiles` + `SourceFilesNote` so this
  and `SourceRow` share one fetch-once-and-keep expansion.
- "Rescan album" → new `POST /api/gaps/<id>/rescan`.

**The album page stops guessing (item 4).** `/api/album/tracklist` now takes
`album_ids` or `group_id` and marks **each track** `present`, using the same
MBID-then-title evidence `_missing_for_album_records` uses — so the detail page
and the Fill-gaps count cannot disagree. The mock marked the trailing N tracks
absent, which is wrong for any album whose gaps aren't at the end. Gap tiles now
open that page instead of hijacking the global Fill-gaps cursor (you clicked one
album and landed on a different screen pointed at a different album), and the
fill offered there is scoped to the review group, so it fetches the missing
tracks rather than the whole release over the top of what you own.

**Variant × edition (item 6).** `/api/album/releases` returns two axes. A
*variant* (Original / Remaster / Deluxe) changes the tracklist; an *edition*
(Digital / CD / Vinyl) is the same tracklist pressed differently and carries its
own cover art. That second axis is the whole point of the feature — the Cover
Art Archive's release-group image is whichever release it happened to pick,
which is how a vinyl-tagged copy shows a photograph of the disc where the sleeve
belongs. Each variant defaults to its digital edition, the likeliest to have a
correct front. Backward-compatible: `releaseMbid`, `title`, `disambiguation`,
`year`, `trackCount` and `country` are all still on the variant, so
`Library.jsx`'s release picker needed no change.

**Compilations exist (item 5).** They were in
`ARTIST_DISCOGRAPHY_EXCLUDE_DEFAULT`, so an artist's best-known release simply
did not appear in the UI. Removed from the exclusion; added
`_effective_release_type()` and passed it through so the frontend groups
Albums / EPs / Singles / Compilations / Soundtracks / Live / Other without a
lookup table of its own.

**Similar albums (item 10).** `/api/album/similar` rolls a similar-artists
lookup up to one owned album per similar artist. ListenBrainz's labs
similar-artists dataset is the primary source, merged with Last.fm's
`artist.getsimilar` when `LASTFM_API_KEY` is set; the two score on different
scales, so they're merged on rank position and an artist both agree on ranks
first. Cached 24 h. Every row is attributed to the artist being viewed.

**The queue walk (§10 bullet).** When the focused album leaves the filtered list
— you picked a source and it went `downloading`, it completed, you skipped it —
the cursor lands on whatever took its slot, which is the next album. It used to
snap to `items[0]`, sending you to the top of a 46-album rail after every pick
and re-offering albums you'd just dealt with.

## Decisions worth keeping

**The scoped rescan walks outside the lock.** `rescan_group_from_disk` copies
the album records out under `_review_lock`, walks the folders unlocked, then
re-acquires to merge. The walk is up to 400 `stat`s per folder and the lock is
process-wide and wanted by every 2 s poll — the exact pattern the README's
"never hold `_review_lock` across I/O" rule exists for, and the same shape
`api_gap_detail` and `_run_group_source_search` already use. It also reuses
`_album_tracks_with_disk`, the narrow walk the duplicate-file report uses
(non-recursive, never the library root, skipped for a directory holding
implausibly more audio than the album has tracks), rather than inventing a
second one. When the walk finds files Navidrome hasn't indexed it nudges a
Navidrome scan, because otherwise they'd read as "only on disk" forever.

**Queue navigation is positional, not a server `nextId`.** §10 offered either.
`_gaps_view` already returns a stable, ordered list across polls, so the index
is sufficient and it costs no API change. The subtlety: the rail-order snapshot
only updates once the cursor has *settled* (`sel === selGap`). Writing it on
every `items` change would erase the position the walk needs during the render
where the album disappears, and the walk would silently fall back to the top —
the exact bug it exists to fix.

**`INDEX_SCAN_VERSION` → 2.** Because compilations were excluded *outright*,
every existing index is missing rows rather than merely stale, and a TTL
expiry wouldn't have expressed that. `release_groups` also gains a
`secondary_types` column via an idempotent `ALTER` guarded on
`PRAGMA table_info` — `CREATE TABLE IF NOT EXISTS` never adds a column to a
database that already exists. Secondary types are stored **raw** rather than
pre-collapsed to a display label, so the grouping can change later without
re-scanning every artist against MusicBrainz.

**`Cover` degrades through a chain.** It now takes `fallbackUrl` and tries
requested art → fallback → deterministic gradient. Without it, a per-release
cover the Archive doesn't hold would drop straight to a coloured rectangle,
which is a worse outcome than showing the release-group's sleeve.

**Neither similarity source failing is fatal.** Both are wrapped
independently; if both fail the answer is an empty list and the shelf doesn't
render. A shelf that isn't shown beats an album page that errors.

  release-group with a vinyl pressing (the case that motivated it); and whether
  the similar-albums shelf finds anything at all on a partly-indexed library —
  it can only show artists that are both owned *and* indexed.

  session, so it isn't this session's to commit. `design_handoff_lb_bot_frontend/`,
